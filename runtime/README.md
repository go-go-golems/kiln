# Kiln runtime: launchers for `kiln-program/1`

A consumer that wants to run a Kiln program does not import the compiler. It commits an export and loads it with one
of two launchers, each a single file the consumer vendors byte-identical (with a header naming this source).

| File                        | Runs                                  | Backends                                              |
| --------------------------- | ------------------------------------- | ----------------------------------------------------- |
| `webgpu/launch.ts`          | the WGSL kernels in a browser or Deno | WebGPU                                                |
| `python/kiln_launch.py`     | WGSL or CUDA kernels from Python      | `wgpu` (wgpu-native), `cuda` (ctypes over NVRTC and the driver API) |

## Making an export

```bash
node scripts/kiln-export.mjs --preset W-12 --param height=1080 --param width=1920 --out blur-1080p.json
node scripts/kiln-export.mjs --script my-program.js --target rtx5090 --out my-program.json
node scripts/kiln-export.mjs --help
```

The schedule is chosen for `--target` (default `webgpu`: WebGPU's guaranteed limits, so the export runs on any
adapter). The export records the script's path and SHA-256, the parameter values, the target and `codegen`.

## The format

```text
format    "kiln-program/1"
name      program name
codegen   emitter version (kiln-codegen/N); a different value means different sources
target    { id, name } the schedules were chosen for
params    parameter values the program was compiled with
source    { path, sha256 } of the project script
inputs    [{ name, buffer, shape, dtype }]          dtype "f32" or "u8"; row-major, contiguous
outputs   [{ name, buffer, shape, dtype }]          always f32
buffers   [{ id, dtype, elements, bytes, name?, data? }]
            bytes: elements × 4 for f32; elements rounded up to a multiple of 4 for u8 (packed four to a word)
            data:  base64 little-endian fp32 values of a data constant (weights, tables), uploaded once
kernels   [{ name, identity, row, reads, writes, grid, block, smemBytes, dispatch, shape, inShapes, inDtypes, wgsl, cuda }]
            in launch order; reads are buffer ids in argument order, writes is one buffer id
            name = <emitted name>__<identity>, also the CUDA entry symbol, so a profiler trace names the computation
            CUDA: launch grid×1×1 blocks of block×1×1 threads, no dynamic shared memory (it is declared statically)
            WGSL: entry point "main"; bindings 0..n-1 are reads, n is the output; dispatch is [x, y, 1] with
                  x = min(grid, 65535), y = ceil(grid / 65535), and the shader skips block ids ≥ grid
```

## Tests

`runtime/test/fixtures.mjs` compiles five cases (one kernel; a grid past 65,535 workgroups; three chained kernels;
weights as data constants; a u8 input) and writes each export with expected outputs from the reference evaluator.
Inputs are regenerated by an integer formula on both sides, so no input files exist.

```bash
node runtime/test/fixtures.mjs /tmp/kiln-fixtures
node runtime/test/webgpu-roundtrip.mjs --fixtures /tmp/kiln-fixtures            # headless Chrome, needs a GPU
python runtime/python/kiln_launch.py check /tmp/kiln-fixtures --backend wgpu     # needs numpy and wgpu
python runtime/python/kiln_launch.py check /tmp/kiln-fixtures --backend cuda     # needs an NVIDIA GPU
```

Both GPU tests are outside `pnpm test`, which must pass on a machine without a GPU.
