# Stack and unbind structural batch

## Scope and source semantics

This batch adds `torch.stack`, `aten.stack.default`, `torch.unbind`, `aten.unbind.int`, and tensor `.unbind()` to the FX importer. The source behavior follows the official [PyTorch 2.9 stack API](https://docs.pytorch.org/docs/2.9/generated/torch.stack.html) and [PyTorch 2.9 unbind API](https://docs.pytorch.org/docs/2.9/generated/torch.unbind.html). The exact API HTML bytes and SHA256 manifest are archived in `sources/pytorch-2-9-structural-docs-v1.tar.gz` and `sources/pytorch-2-9-structural-docs-archive-v1.json`; no PyTorch implementation code was copied. The materialized PassNet graphs include an mmseg convolution→stack→sum→concat family, mmpose arithmetic→unbind→permute, and timm linear→reshape→permute→unbind→transpose.

Stack inserts a dimension and concatenates equal-shaped, equal-dtype tensors. Unbind returns a tuple of views after removing the selected dimension. The importer checks dimension bounds, input shape and dtype agreement, output metadata and output count. It lowers stack to singleton-dimension `N.reshape` operations followed by `N.concat` when more than one input exists. It lowers each unbind result to `N.slice` followed by `N.reshape` that removes the singleton dimension. The unbind result remains a structured list of IR expressions; the existing tuple/getitem path selects its elements. Unbind outputs are not marked as fresh ownership, so later in-place mutation of their aliases remains rejected under the importer's existing rule.

The new logic lives in `integrations/passnet/fx_layout.py` and is dispatched through the existing `fx_import.py` path. No new Kiln tensor IR operation or alternate compiler path was added. This decomposition also gives the optimizer a useful target: fold stack→reduction, avoid materializing unbind views, and simplify reshape/slice/transpose index maps.
